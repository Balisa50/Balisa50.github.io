Technology news is unreadable at volume. Hundreds of thousands of articles a day globally, most of it patch notes, gadget sales, recycled press releases and thirty outlets rewriting the same wire story. I wanted a feed that did the synthesis, scored each story so I could skim rather than read, and covered six regions rather than just the American one.

I also wanted it to read like editorial rather than like a bot summarising headlines. That turned out to be a prompt problem, not a model problem.

## Why these calls and not the obvious ones

<TradeOffs>

<TradeOff chose="a chain of route handlers" over="one cron per region">

The free plan allows a single daily cron. The obvious response is to accept covering one region, or to pay.

Instead the daily cron hits the global route, and each route fires the next one on its way out with a shared secret header. Six regions, one cron, no fan-out, and each link independently fits inside the sixty-second budget because it only ever handles one region. If a link breaks the chain stops there and tomorrow's run starts over from the top, which is an acceptable failure mode for a news feed and a terrible one for anything transactional.

</TradeOff>

<TradeOff chose="deduplicating before the model call" over="deduplicating the output">

NewsAPI returns the same story from thirty outlets quoting the same two wires. Generating summaries and then merging duplicates is the natural order and it is exactly backwards on a budget.

Slugifying the headline and checking the database first means roughly seventy percent of candidates never reach the model. The cheapest call is the one you do not make, and on a pipeline running unattended every day that ratio is the difference between affordable and not.

</TradeOff>

<TradeOff chose="the small fast model" over="the larger one">

Article synthesis is high volume and low stakes per token. If today's piece is mediocre, tomorrow's run replaces it. That is a very different risk profile from a legal citation or a credit score, and it should buy a different model.

The small model is a third of the cost and the strict editorial prompt does the work the extra capability would have done. Roughly four hundred words of explicit constraints: the headline is a verdict, follow the money first, name names, short paragraphs, no em dashes, an explicit list of banned openers, and a falsifiable prediction at the end. The output reads sharp because the prompt is sharp, not because the model is large.

</TradeOff>

<TradeOff chose="a direct fetch to the provider's endpoint" over="the official SDK">

The Node SDK pulls in dependencies that do not run on the edge runtime. Thirty lines of direct fetch do.

Edge keeps cold starts under about 100 milliseconds against roughly 800 for the Node runtime, which sounds like a micro-optimisation until you remember that six chained calls are each racing a sixty-second wall. Seven hundred milliseconds of cold start per link is more than a second of the budget spent on nothing.

</TradeOff>

<TradeOff chose="one article per region per run" over="three">

The original target was three per region. It blew the timeout, repeatedly.

Six good articles that arrive beats nine that time out at article nine and lose the whole region's batch along with them. Half the iteration history on this project is the same loop: add a capability, blow the timeout, remove the capability. Reddit and Hacker News sub-pipelines went in and came back out for exactly this reason.

</TradeOff>

<TradeOff chose="keeping stale articles" over="expiring them on schedule">

A nightly job used to delete anything older than 48 hours to keep the feed fresh. Sensible, until model credits ran out. Generation stopped and expiry did not, so the feed emptied itself with no way to refill.

The expiry cron is disabled and the route returns a refusal even when triggered by hand. An old feed is a degraded product. An empty feed is a dead one. When two failure modes are not symmetric, the automation should not treat them as if they are.

</TradeOff>

</TradeOffs>

## What broke

<PostMortem
  title="A stale environment variable killed five of six regions and nothing reported it"
  symptom="Regional content stopped updating. The global region kept publishing normally, so the feed looked alive on the front page. I did not notice for weeks."
  cause="The site URL was hardcoded to an auto-generated deployment URL that stopped resolving after a project rename. The chain fires the next region with a plain fetch and a `.catch(() => {})` on the end, so the DNS failure was swallowed silently. Global publishes first and does not depend on the chain, which is why the one region I looked at was the one region that worked."
  fix="Read the base URL from the deployment's own environment rather than hardcoding it, and log chain handoff failures instead of discarding them."
  cost="Weeks of partial output, undetected, on a system whose entire purpose is running unattended."
  lesson="Fire-and-forget plus no observability is how a bug hides for a month. If a failure has no consequence you will see, it has no consequence you will fix. The catch block that swallowed the error was two characters long and cost more than any other line in the project."
/>

<Note>

A second one worth recording because it is specific to working on Windows. A build failed with a TypeScript error pointing into a completely different project's Prisma config. A OneDrive sync had deposited a copy of another repository inside this one, and the compiler was dutifully type-checking it. Cross-project filesystem leakage is a real hazard when your source directory is inside a syncing cloud folder, and it is the reason my active repositories now live outside it.
